# Cas de régression pixel — un par ligne : <nom> <frames> [<entrées>]
#
# Le ROM est construit depuis le projet demo/ : ces images décrivent un
# état SAIN de la demo, pas un rendu quelconque. Changer demo/ change les
# références (regress.sh --bless).
#
# Entrées : "premiere-derniere:TOUCHE" séparées par des virgules.
#   A B U D L R  S=Start  E=Select  W=R
#
# RÈGLE À NE PAS CASSER : la route ne doit traverser AUCUN warp. Une
# capture qui dépend d'un chargement de scène devient sensible au timing
# et la comparaison octet à octet perd son sens. Le trajet ci-dessous
# longe la plaine sans sortir de la scène de boot.

# La plaine porte un bloc de PNJ « regr_ » qui exerce la boucle
# d'affichage : un a cheval sur le bord gauche (9e bit de X), deux qui
# marchent sur itineraire fixe (animation de pas), un qui change
# d'apparence en route (Change Graphic), un en priorite au-dessus. Sans
# eux, la demo n'avait que deux PNJ et la boucle n'etait quasiment pas
# couverte. Leur nombre est VOLONTAIREMENT modeste : au-dela, le moteur
# perd des frames et les PNJ marchent moins vite, ce qui rend deux
# versions du moteur incomparables.

# écran de boot stabilisé — attrape tout ce qui touche au chargement de
# scène, aux palettes, au HUD permanent
boot 200

# le héros marche puis parle à un PNJ : dialogue en cours de frappe.
# C'est ce cas qui a attrapé le bug tcc-816 « variable déclarée dans un
# case » (rangée de cœurs du HUD corrompue en silence).
d340 340 210-290:R,300-302:D,310-311:A

# même trajet, dialogue entièrement révélé
d460 460 210-290:R,300-302:D,310-311:A
